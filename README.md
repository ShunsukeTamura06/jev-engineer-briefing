# Decision Model ― エンジニア向け勉強会資料

文章を書かず、決められた選択肢から「選ぶ」だけの AI（Decision Model）を扱う、エンジニア向け勉強会（約15分）のスライドです。一般名で説明し、事実の出どころを示すときだけ Jev（TypeSafe AI）・Kev（オープンソース）・OpenAI Decisions API の固有名詞を使います。

主張は1つ：**判断だけを切り出すと、同じ水準の判断が桁違いに速く・安くなる（時間 25分の1・費用 75分の1）。ただし判断力は最先端の LLM に届かないので、確率で振り分けて「全件に置き、迷ったものだけ LLM と人へ」回す。**
各スライドは「事実 → その読み方」の形にしてあり、日銀の声明文を「タカ・中立・ハト」に分類する例を通しで使います。

## 構成（本編12枚＋補足1枚・約15分）

流れは「概要 → 説明 → すごいところ → 課題」。

| # | 区分 | スライド | 役割 |
|---|---|---|---|
| 1 | 概要 | 表紙 | Decision Model ― 書かずに、「選ぶ」だけの AI |
| 2 | 概要 | Decision Model とは | 実際の API（例：Jev）。注目箇所に①〜⑤の印。「JSON も文章では？」への答え |
| 3 | 概要 | デモ | LLM と Kev で同じ声明文を分類（動画） |
| 4 | 説明 | なぜ速いのか | 書く工程がないから。70〜500ms、入力のみ課金 |
| 5 | 説明 | 3つの型 | noul（はい／いいえ）・choice（選択肢から1つ）・score（段階評価）を、同じ問い合わせへの実際の JSON で比較 |
| 6 | 説明 | 確率の意味 | LLM＝選ばれる確率、Decision Model＝合っている確率。実例（迷惑メール）と確率での振り分け |
| 7 | すごいところ | 10秒 → 0.4秒 | 最先端モデルとの一致率は同じ68%のまま25倍速い（費用も75分の1） |
| 8 | すごいところ | 4つの拡張 | 判断は昔からできた、新しいのはコストの桁。まれに→常に／代表だけ→全部／一律→一人ずつの基準／一つ→多数の視点 |
| 9 | すごいところ | 活用例 | 答えの3つの型（選択肢から1つ／はい・いいえ／段階評価）を色で示す。問いを書くだけでできる判断6つ（間違えても後ろで拾える判断） |
| 10 | すごいところ | 他社モデルの登場 | 3週間で7つ：Jev・Kev・Laya・OpenAI・Cloudflare Clef・Perplexity Decider・AWS Strands Decider。画像が読めると動画を1秒ごとに判定 |
| 11 | 課題 | Decision Model の課題 | 判断力は最先端に届かない（一致率 73% 対 68%）／公式が挙げる苦手（計算・日付の比較・書いたとおりに読む・選択肢の順番）／日本語／理由なし／外部 API |
| 12 | ― | まとめ | 判断を全件に置き、迷ったものだけ LLM と人へ |
| 13 | 補足 | 社内で使うには | Kev を 動かす・つなぐ・測る |

Structured Output との違い、BERT 等との違い、logprobs、40〜200倍の宣伝の読み方などは、各スライドの発表者ノート（想定質問）に置いてある。
