一番大事なたとえ

LLM は記述式、Jev はマークシート

LLM
記述式文章で書く

問1　この声明はタカ派か、ハト派か。

物価が見通しどおりに上がれば利上げを続けるとしており、引き締めに前向きな内容のため、タカ派と判断します
Jev
マークシート自信の分だけ濃く塗る

問1　この声明のスタンスは？

タカ82%
中立15%
ハト3%

普通のマークシートは1つだけ塗る。Jev は全部の選択肢を、自信の分だけ濃く塗る。その濃さが確率

問題も選択肢もその場で配れる（追加学習なし）。選択肢の外は答えない。昔ながらの分類モデル＝問題と選択肢が印刷済みの専用マークシート（変えるには学習し直し）。確率の数字は説明用。

まとめ

「書く」と「選ぶ」を、分けて設計する

マークシートに向く

選択肢が決まっている／件数が多い／速さが要る判断（分類・振り分け・承認・採点・監視）

記述式のままがよい

文章・要約・コードを書く／計算する／理由の説明が必要な判断

LLM　―　記述式。何でも書ける。遅く、高い

Jev　―　マークシート。書けない。速く、安い

だから、選ぶ仕事は全件に置き、迷ったものだけ LLM と人へ

まず手元の分類1つで、正解率と「82% が本当に82% か」を測る。

API の形

渡すのは「状態」と「問いと選択肢」だけ

// POST /v1/systemone { "model": "jev-latest", "state": "基調的な物価上昇率が見通しに沿って…", "questions": { "stance": { "type": "choice", "instructions": "金融政策のスタンスは？", "criteria": { "hawkish": "引き締めに前向き", "neutral": "どちらとも言えない", "dovish": "緩和に前向き" } } } }
// 返ってくるのは、選択肢と確率だけ { "model": "jev-latest", "answers": { "stance": { "type": "choice", "choice": "hawkish", "probabilities": { "hawkish": 0.82, "neutral": 0.15, "dovish": 0.03 }, "confidence": 0.6 } }, "usage": { "input_tokens": 210, … } }
choice　選択肢から選ぶ（最大255） noul　はい／いいえの確率 score　2〜10段階の評価
